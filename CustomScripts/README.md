# CustomScripts — скрипты Altium Designer 20+

Набор из восьми скриптов DelphiScript для повседневных задач PCB/схемы. Примеры в репозитории (`!SCRIPTS`) не изменялись.

Параметры согласованы с заказчиком (см. [`QUESTIONS.md`](QUESTIONS.md) — вопросы закрыты).

## Установка

У каждого скрипта **свой** `.PrjScr` с **одним** `.pas` (как в `!SCRIPTS/Fillet/Fillet.PrjScr`). Altium компилирует **все** `.pas` из проекта в **одно** пространство имён: общий `CustomScripts.PrjScr` со всеми модулями даёт `Identifier redeclared` (часто на `R` в `Panelizer.pas`, даже если запускали другой макрос).

| Скрипт | Проект | Процедура Run Script |
| --- | --- | --- |
| Скругления трека | `TrackCornerFillet.PrjScr` | `StartTrackCornerFillet` (`_StartTrackCornerFillet`) |
| DXF контуров | `DxfOutlineExport.PrjScr` | `StartDxfOutlineExport` |
| Панелизация | `Panelizer.PrjScr` | `StartPanelizer` |
| Десигнаторы схемы | `SchDesignatorReset.PrjScr` | `StartSchDesignatorReset` |
| BOM Excel | `BomExport.PrjScr` | `StartBomExport` |
| Полигоны GND | `GroundPolygons.PrjScr` | `StartGroundPolygons` |
| Мастер PCB | `PcbWizard.PrjScr` | `StartPcbWizard` |
| Десигнаторы на PCB | `PlaceDesignators.PrjScr` | `StartPlaceDesignators` |

1. **File → Open Project** и откройте нужный `*.PrjScr` **или** добавьте каждый проект в **Preferences → Scripting System → Project Scripts** (Installation scripts), чтобы пункты появились в **DXP → Run Script**.
2. Запускайте **уникальную** процедуру `Start…` из таблицы (не внутренние функции).
3. Формы (`.dfm`) лежат рядом с `.pas` (Altium подхватывает их по имени; в `.PrjScr` формы не перечисляются).
4. Файл `CustomScripts.PrjScr` — только заметка, **без** списка скриптов. Не собирайте восемь `.pas` в один проект.

Диалог открывается даже без открытого PCB/схемы; работа с платой — только по OK.

Интерфейс диалогов — светлый (Segoe UI, форма `Color = clBtnFace`). У `TButton` нет свойства Color — в `.dfm` его нет. Подписи в `.dfm` — коды `#NNNN` **без пробелов между кодами** (UTF-16), как грузит Altium. Тексты MessageBox берутся из скрытых `TLabel` на форме (кириллица WinAPI не из UTF-8 в `.pas`). Десятичные в полях: и точка, и запятая (`3.2` / `3,2`); замена символов — цикл, без set-литерала rfReplaceAll.

Идентификаторы в коде — на английском, с префиксом скрипта (`PanR`, `FilBoard`, …), чтобы даже случайная сборка нескольких файлов не давала `redeclared`.

## Картинки в диалогах

У **каждого** скрипта всплывающее окно: слева `TImage`, справа параметры и OK/Отмена.

Положите BMP (предпочтительно) или PNG в [`images/`](images/) рядом с `.PrjScr`:

| Скрипт | Файл |
| --- | --- |
| TrackCornerFillet | `images/Fillet.bmp` |
| DxfOutlineExport | `images/DxfExport.bmp` |
| Panelizer | `images/Panelizer.bmp` |
| SchDesignatorReset | `images/SchAnnotate.bmp` |
| BomExport | `images/BomExport.bmp` |
| GroundPolygons | `images/GroundPolygons.bmp` |
| PcbWizard | `images/PcbWizard.bmp` |
| PlaceDesignators | `images/PlaceDesignators.bmp` |

Замените файл своим рисунком. Если файла нет, диалог **не падает** — показывается подсказка. Путь берётся из открытого `.PrjScr` (`GetWorkspace` → папка проекта), **не** из `ParamStr(0)` (в Altium это не EXE и даёт AV).

## Устранение сбоя «Разрушительный сбой»

- Сохраняйте `.pas` как **UTF-8 с BOM** (как сейчас в репозитории). UTF-8 без BOM с кириллицей ломает старый DelphiScript.
- Не вызывайте `ParamStr` — его нет в скриптах Altium.
- Запускайте уникальную `Start…` / `_Start…` того проекта, который открыт (см. таблицу выше).
- Картинки: `images\*.bmp` рядом с PrjScr; отсутствие файла безопасно.
- В каждом `.PrjScr` только **один** `.pas` (как в примере Fillet), без PNG и без `.dfm` отдельными документами.
- Если Altium открывает `Panelizer.pas` и пишет **Identifier redeclared** — в проект попало больше одного `.pas`. Закройте общий проект и откройте нужный `*.PrjScr`.

## Скрипты

### 1. Скругления углов трека — `TrackCornerFillet.pas`

**Назначение.** Ставит скругления (fillet, `IPCB_Arc`) заданного радиуса на **выбранные углы**: в вершине должны быть выделены оба сегмента. Две стороны квадрата = **один** угол, контур сам не добирается.

**Как запускать.** Откройте `TrackCornerFillet.PrjScr`, PCB, выделите **оба сегмента угла** (и дугу, если она уже есть), DXP → Run Script → `StartTrackCornerFillet`.

**Параметры.** Радиус в мм (по умолчанию **0,5**). Допускаются `0.5` и `0,5`. **Радиус 0** снимает скругления (треки продлеваются до угла, ошибка не выдаётся). Если на выбранных углах уже есть дуги и R>0, один раз спрашивается: «переделать?»

**Поведение.** Угол — ровно два выделенных сегмента в вершине. Повтор с новым радиусом обновляет **все выбранные** углы (снимок дуг до удаления). Слишком большой радиус — вершина пропускается.

**Ограничения.** Не скругляет стык трек–дуга, если дуга не является скруглением между двумя треками. Не работает с `IPCB_Connection` (крысы).

### 2. DXF контуров слоёв — `DxfOutlineExport.pas`

**Назначение.** Экспорт выбранных слоёв PCB в DXF: геометрия — **линии и дуги полного контура**, не залитые полигоны и не осевые линии нулевой ширины.

**Как запускать.** Откройте `DxfOutlineExport.PrjScr`, PCB активен → Run Script → `StartDxfOutlineExport`. Чеклист слоёв, OK, файл `.dxf`.

**По умолчанию отмечены:** все медные слои; Top Overlay / Bottom Overlay; отдельный слой **HOLES**. Keep-out, механика, маска, паста — в списке, но сняты.

**Что экспортируется.**

| Примитив | Как рисуется в DXF |
| --- | --- |
| Трек / дуга-трек | Контур ширины (LINE + ARC), не центрлайн |
| Площадка | Контур формы на медном слое |
| Переходное | Внешнее кольцо на меди |
| Заливка / регион / полигон | Только контур LINE/ARC |
| Отверстия площадок и переходных | **CIRCLE** на слое DXF `HOLES` (не смешиваются с медью) |
| Шелкография | Отдельные слои Top Overlay / Bottom Overlay |
| Текст | Пропускается |

Единицы — мм. ASCII DXF R12. Файл пишется скриптом напрямую, **без** `ExportDXF` Altium.

**Ограничения.** Сложные регионы с вырезами могут быть упрощены до внешнего контура. 3D тела не экспортируются. Boolean-объединение overlapping-геометрии не выполняется. Штриховой текст шелкографии не обводится.

### 3. Панелизация — `Panelizer.pas`

**Назначение.** Новый `.PcbDoc`, массив исходной платы, **путь фрезы** вокруг контура каждой платы (смещение = радиус фрезы) с **разрывами** ширины перемычки (web, по умолчанию 4 мм, **без отверстий**) и **прямоугольная внешняя рамка** = габарит массива **плюс поле с каждой стороны** (по умолчанию 10 мм) на механическом слое.

**Параметры по умолчанию**

| Параметр | Значение |
| --- | --- |
| Столбцы (X) × ряды (Y) | **4 × 2** (8 плат) |
| Зазор плата–плата | **2 мм** |
| Поле до края панели | **10 мм** |
| Ширина перемычки (web) | **4 мм** |
| Радиус фрезы (смещение пути) | **1 мм** |
| Перемычки | Разрывы в пути фрезы шириной web, **без сверловки** |
| Механический слой контура | Mechanical 1 |

Массив: `IPCB_EmbeddedBoard`. Путь фрезы — треки/дуги вокруг платы; внешняя рамка — прямоугольник bbox+поле.

**Ограничения.** Embedded Board Array в скриптах AD не всегда копирует шелкографию панели. Сложный непрямоугольный контур исходной платы копируется ограничено.

### 4. Сброс и обновление десигнаторов схемы — `SchDesignatorReset.pas`

**Назначение.** Перенумерация **всего проекта** (все листы). Порядок Altium **Down then Across**: сначала колонка сверху вниз, затем следующая слева направо (не Across then Down). Счётчики префиксов общие на проект (R1 не начинается заново на каждом листе).

**Параметры.** По умолчанию: перенумеровать + все листы. Опция сброса в `?` выключена, но доступна. Заблокированные десигнаторы не меняются.

**Ограничения.** ECO на PCB автоматически не выполняется. Мультиканальность: могут понадобиться Compile + Annotate в GUI.

### 5. Выгрузка BOM — `BomExport.pas`

**Назначение.** BOM в **Excel** без Excel COM: SpreadsheetML 2003 XML, файл **`.xls`**, Excel открывает его нативно.

**Столбцы точно в этом порядке:** `Comment`, `Designator`, `Description`, `Quantity`, `Value`.

**Состав.** **Все** компоненты: DNP, графические, NoBOM, механические — ничего не исключается. Параметры схемы читаются обходом `ISch_Parameter` / `eParameter`.

**Группировка.** Ключ Comment + Value + Description (footprint учитывается внутри, отдельного столбца нет). Designator — склейка списка.

Рядом пишется `*.bom.settings.xml`.

**Ограничения.** Это SpreadsheetML, не бинарный BIFF `.xls` и не `.xlsx`/COM. Вариант проекта — текущий; отдельный выбор Variant в диалоге не делается.

### 6. Земляные полигоны по контуру — `GroundPolygons.pas`

**Назначение.** Заливки (`IPCB_Polygon`) по **контуру платы** на всех сигнальных медных слоях, цепь **GND**.

**Зазоры скрипт не задаёт** — ими управляют **правила проектирования**. Поля зазора в диалоге нет.

Стиль по умолчанию — solid. Если полигон этой цепи на слое уже есть — спросить заменить/пропустить.

**Ограничения.** Внутренние plane-слои не заливаются как signal polygon. Если контура нет — bounding box. Rule Wizard не вызывается.

### 7. Мастер новой PCB — `PcbWizard.pas`

**Назначение.** Вся настройка в диалоге: размер, keep-out со скруглениями, крепёж, слои, полигоны GND, вскрытие маски, сетка.

**По умолчанию.** 80×50 мм, скругление 2 мм, **4 медных слоя**, **4 отверстия по углам**, сетка **0,1 мм**, отверстие **3,2 мм** (ввод `3.2` и `3,2`). Отступ 4 мм.

**Ограничения.** Полная перестройка layer stack (2→4→6) через скрипт в AD20+ ненадёжна — стек лучше задать шаблоном / Layer Stack Manager. «Вскрытие маски» — заливка на Top/Bottom Solder по контуру, не правило Solder Mask Expansion площадок.

### 8. Авторасстановка десигнаторов на PCB — `PlaceDesignators.pas`

**Назначение.** Только **шелкография** (Top/Bottom Overlay). Если выделены компоненты — только они; **если выделения нет — все**.

Кандидаты: сверху/снизу/слева/справа от courtyard. Текст имени двигается через `ChangeNameAutoposition := eAutoPos_Manual` и `IPCB_Text.MoveToXY` (присвоение `XLocation` в AD не сдвигает десигнатор). 0° или 90°. Скрытые (`IsHidden`) можно пропускать.

**Ограничения.** Нет courtyard — используется `BoundingRectangleNoNameComment`. При плотной шелкографии остаётся лучший кандидат с предупреждением.

## Общие замечания по API

Используются только известные интерфейсы: `PCBServer`, `IPCB_Board`, `IPCB_Track`, `IPCB_Arc`, `IPCB_Pad`, `IPCB_Via`, `IPCB_Polygon`, `IPCB_Component`, `SchServer`, `ISch_Document`, `ISch_Component`, `Client` / `ResetParameters` / `RunProcess`.

Где API ненадёжен, сделан best-effort и описано ограничение — пустых заглушек нет.

## Соответствие примерам

Стиль близок к скриптам в `!SCRIPTS`: формы `.dfm`, `PCBServer.PreProcess`/`PostProcess` для Undo, `Board.SelectecObjectCount` (историческая опечатка API), `MMsToCoord` / `CoordToMMs`, `MkSet`.
